B-VISUAL-TOKEN-BUDGET-01 — Bucket B color comparison

Side-by-side of every bucket B off-system color flagged by the no-restricted-syntax token-lint rule, with the resolved hex of the flagged Tailwind utility next to the resolved hex of the nearest existing token in src/app/globals.css. Bucket B is, by definition, the set where the remap is not 1:1 — every row shifts the rendered color by some amount. Tailwind palette hex are the standard reference values; this project renders them via oklch in v4, so on-screen sRGB can differ by a sub-perceptual amount. --destructive is stored as oklch(0.577 0.245 27.325) (exactly v4 red-600), shown as ≈#dc2626.

Every component surface that carries a bucket-B off-system color, the utilities it uses, and what the color is doing there. The Example column under each swatch below shows the exact flagged source line.

Frequency — how often each color appears

Two numbers per remap target: Flagged uses = how many of the off-system sites in this audit would land on that token; Already in codebase = how many times that token is already referenced across src/ today. A target with a big “already” number is a well-trodden token — remapping onto it is low-risk and consistent.

Direct answer on ≈#dc2626 (--destructive): only 3 flagged sites map to it (text-red-700 ×1, text-rose-700 ×2), but it is the app’s canonical error color — already referenced ~57× across the codebase (text-destructive ×50, var(--destructive) ×4, plus variants). So those 3 stragglers just join a token that already shows up a lot.

Off-system color(s) → target token Flagged uses Already in codebase Read

text-red-700 / text-rose-700 → --destructive ≈#dc2626 3 ~57× Few flagged, but the token itself is everywhere.
text-[#111111] / text-stone-950/800 → --warm-ink 3 17× Near-black warm ink; documented collapse for #111111.
text-black → --brand-ink (or --warm-ink) 3 53× (--brand-ink) Two candidate tokens — the judgment call of bucket B.
bg-white → --brand-card 1 23× ≈match; one straggler onto a common surface token.
text-stone-700 → --warm-ink-700 1 — One-off neutral text.
border-stone-400 → --warm-ink-400 1 — One-off neutral border.
bg-stone-200 → --warm-border 1 — ≈match; one-off.
Amber / warning family → no semantic token 31 n/a By far the largest cluster — 31 utility uses across 13 className literals. Strongly argues for inventing a --warning* token (bucket C).
Pale tint backgrounds/borders (emerald/red/rose 50–200) → no semantic token 6 n/a 6 uses across 3 banner literals; need pale success/error tokens (bucket C).

Most-used single utility overall is border-amber-300 (8 sites), then bg-amber-50 (7) and text-white (6). The whole amber family (31 uses) dwarfs every clean-mappable color combined — the warning role is the real gap in the token set.
