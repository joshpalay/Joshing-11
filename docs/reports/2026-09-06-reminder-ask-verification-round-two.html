Headline · the fix did not work

The confirmation toast still never reaches the player. #1607 moved it out of a conditional render so it would always mount — and it does. But it renders at --z-toast (70), underneath the fullscreen crafting screen's --z-takeover (80). On a slow build it sits invisible behind the loader while its own 1.8s dismiss timer runs, and has already expired by the time the loader clears. The first fix traded a conditional-render bug for a z-index one; the player saw nothing either way. Fixed in #1608 by gating on !loading, so the toast starts its life when there is something to show it over.

What this says about the process

The walkthrough earned its keep

#1607 passed typecheck, lint, 96 tests and five style ratchets. None of that could catch a toast painted underneath a takeover layer — it takes a human-shaped pass through the real screen, at real timing, on real infrastructure.

The same is true of round one, which found the original bug. Two rounds, two defects, neither visible to the test suite.

A fix is a hypothesis until it is watched

The first fix was reasoned from the right diagnosis and still failed, because it moved the element into a layer nobody checked. Worth treating "verified by re-walkthrough" as the bar for anything whose whole purpose is to be seen.

Still open · carried from round one

Generation timing remains unmeasured at any real sample size — round one saw a fast build, round two a slow one, from an instrumentation table that had one usable row. It decides how often the crafting screen appears at all, so it is worth letting DailyBuildMetric accumulate before tuning anything around the wait.
